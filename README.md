# 编程培训咨询 Agent

面向编程培训咨询场景的本地单机 Agent 原型。工程上采用“教学样本驱动 + 工具调用 + 审核发布 + 可观测执行轨迹”的闭环架构：学员咨询 → 全量召回已审核教学样本 → 基于学员背景推进对话 → 查询有依据的事实数据 → 低置信度或规则触发转班主任 → 反馈改进与同题回放。

本文档从项目工程视角描述系统分层、模块职责、运行时链路、数据与配置、构建部署、质量保障及已知工程边界。启动细节见启动指南。日常演示采用 `8888` 单端口模式；开发模式使用 `5173` 前端与 `8888` 后端。

## 1. 工程目标与非目标

### 1.1 工程目标

- 提供可本地运行、可演示、可回归测试的咨询 Agent 原型。
- 将“教学样本、知识库、Prompt、工单、会话、审计”统一纳入 SQLite 持久化。
- 通过 Harness 注入式 Loop、Context、ToolRegistry、StreamingGuard 将业务逻辑与运行时机制解耦。
- 通过强制工具调用、审核状态控制、Prompt 版本发布/回滚和转人工规则，约束模型行为。
- 提供 SSE 流式通信、执行轨迹、运行指标导出与同题回放，支撑技术验证与问题定位。

### 1.2 非目标

- 不实现真实支付、实时坐席系统、自动发布 Prompt 或 fine-tune。
- 不提供生产级登录、访问控制或多进程任务协调。
- 不将本地事件与指标解释为真实用户量、咨询转化率或商业收益。
- 执行轨迹不包含隐藏思维链。

## 2. 系统架构与分层

| 层 | 工程职责 | 实现 |
|---|---|---|
| 前端 | 咨询平台与后台管理页面、多轮对话、SSE 流式渲染、历史恢复、停止生成、点赞/点踩 | Vue3、Vite、TypeScript，Pinia 已初始化 |
| API 层 | 聊天 SSE、后台管理接口、页面服务、健康检查、接口文档 | FastAPI |
| Agent 业务层 | 咨询业务、样本、工具、知识检索、Prompt 与优化 | `agent/` |
| Harness 运行时 | 业务无关的循环、上下文、工具协议和缓冲机制 | 注入式 Loop、Context、ToolRegistry、StreamingGuard |
| 数据访问层 | 数据模型与兼容迁移 | SQLAlchemy、SQLite |
| 通信层 | POST SSE、持久化请求 ID/事件序号、心跳、取消与续读 | FastAPI SSE |
| 检索层 | 本地轻量向量检索 | SQLite 保存 256 维字符二元组哈希向量，余弦相似检索 |
| 模型层 | 咨询模型调用 | Qwen-plus，DashScope OpenAI 兼容接口 |
| 测试与验收 | 后端回归、浏览器场景、隔离真实模型验收 | unittest、Playwright + 本机 Edge、`scripts/verify_live.py` |

向量检索是无需下载模型的轻量本地实现，不是 Chroma 或语义 embedding 模型；相似度不等于回答正确率。

## 3. 项目目录与模块职责

```text
agent/                  咨询业务、样本、工具、知识检索、Prompt 与优化
harness/                业务无关的循环、上下文、工具协议和缓冲机制
api/                    聊天 SSE、后台管理与页面服务
db/                     数据模型与兼容迁移
frontend/               咨询平台和后台 Vue 页面
data/                   默认数据库、模拟商品、案例与订单资料
scripts/                样本导入、隔离真实模型/浏览器验收服务
tests/                  后端回归测试
Dockerfile              包含前端的多阶段镜像配置
docker-compose.yml      8888 端口与 state 数据卷配置
```

工程边界约定：

- `harness/` 保持业务无关，不直接承载咨询业务规则。
- `agent/` 承载咨询业务、样本召回、工具实现、知识检索、Prompt 与优化逻辑。
- `api/` 负责协议适配、SSE 生命周期、后台管理与页面服务，不替代业务层规则。
- `db/` 负责模型定义与兼容迁移，保证本地 SQLite 数据可演进。
- `scripts/` 提供样本导入与隔离验收入口，避免验收数据污染默认库。

## 4. 运行时链路

每轮咨询的核心工程链路：

1. API 层接收咨询请求，建立或恢复会话，创建持久化请求 ID 与事件序号。
2. Harness 按注入式 Loop 组织上下文与工具调用。
3. 程序强制调用 `recall_playbook`，获取全部已审核教学样本。
4. 已审核样本按场景加入系统上下文；发布 Prompt 或审核样本后，下一轮生效。
5. 模型按需调用背景分析、能力路径、课程检索、案例检索、知识检索、工单、置信度评估、订单查询等工具。
6. StreamingGuard 按完整句检查安全约束，并限制整轮句数；通常回复 2–3 句。
7. 低置信度、规则命中或主动诉求触发 `handoff`，创建或复用班主任工单。
8. 执行轨迹记录决策摘要、Prompt 版本、工具参数/结果/耗时、错误与兜底状态。
9. 前端通过 SSE 消费流式事件，支持停止生成、取消与续读、历史恢复与反馈。

## 5. 功能模块

| 模块 | 能力 |
|---|---|
| 咨询平台 | 多轮对话、SSE 流式回复、历史恢复、停止生成、点赞点踩 |
| 执行轨迹 | 决策摘要、Prompt 版本、工具参数/结果/耗时、错误与兜底状态 |
| 工单 | 主动诉求、规则或低置信度转人工；统一落库去重；接单与处理 |
| 训练样本 | 问题、标注答案、回答原因、场景、来源；编辑、审核、删除和审计 |
| 套路库 | 展示审核样本，与每轮召回和系统上下文同源 |
| 知识库 | 人工填答、审核、确认入库、本地向量检索；修改后重新审核 |
| Prompt | 基础内容编辑、完整预览与下载、真实红线测试、版本发布及回滚 |
| 半自动改进 | Qwen 分析差评、生成候选/理由/diff，人工审核后发布 |
| 回放与观测 | 同题版本对比、只读工具、运行指标导出与审计 |

## 6. 核心业务规则与工程约束

- 询价先确认学习意向，不主动报具体价格；意向明确后由班主任谈价。
- 信息不足先了解学历、基础、城市、学习目标和投入。
- 不编造政策、就业承诺或真实案例；样本也不能覆盖业务铁律。
- 每轮由程序强制调用 `recall_playbook` 获取全部已审核样本。
- 已审核样本按场景加入系统上下文；发布 Prompt 或审核样本后下一轮生效。
- 通常回复 2–3 句。安全 Guard 按完整句检查，并限制整轮句数。
- 训练样本或知识修改后需重新审核；运行时服从当前业务铁律。
- Prompt 与样本的审核/发布状态是运行时输入的一部分，不允许绕过审核直接生效。

## 7. 已注册工具

| 工具 | 用途 |
|---|---|
| `recall_playbook` | 全量召回已审核教学样本 |
| `analyze_student` | 从对话提取学员背景 |
| `generate_plan` | 生成能力路径，不承诺招生结果 |
| `course_search` | 检索已登记的模拟商品资料 |
| `student_cases` | 检索已核验、有来源、背景匹配的真实案例 |
| `knowledge_search` | 检索已审核知识及来源版本 |
| `handoff` | 创建或复用班主任工单 |
| `assess_confidence` | 记录模型自评，低于 `0.5` 转人工 |
| `order_query` | 当前会话绑定的只读脱敏订单 |

工具注册与调用由 Harness 的 ToolRegistry 管理；执行轨迹记录工具参数、结果与耗时，便于回归与审计。

## 8. 数据、配置与持久化

默认数据库为 `data/app.db`。模型 Key 保存在不提交的 `.env`；模型、数据库位置和差评阈值配置见 `.env.example`。

| 数据/配置 | 工程说明 |
|---|---|
| `data/catalog.json` | 带来源标记的模拟商品，不是实际招生政策 |
| `data/student_cases.json` | 默认空；只有 `verified=true` 且有来源的真实案例才返回 |
| `data/demo_orders.json` | 脱敏模拟订单；`DEMO-001` 绑定 `demo-session`，无支付和订单写入 |
| SQLite | 已审核样本、知识、Prompt、会话和工单重启保留 |
| `.env` | 模型 Key 与运行配置，不提交 |
| `data/app.db` | 默认本地数据库 |
| `data/acceptance_live.json` | 真实模型验收报告输出 |

配置与代码分离；真实模型验收使用隔离数据库，避免污染默认演示数据。

## 9. 构建、启动与部署

以下假设项目位于 `D:\codex`，Python、uv 和 Node/npm 已可用。

```powershell
Set-Location D:\codex
uv sync --locked
if (!(Test-Path .env)) { Copy-Item .env.example .env }
# 首次启动：在 .env 填写 DASHSCOPE_API_KEY

Set-Location D:\codex\frontend
npm.cmd ci --no-audit --no-fund
npm.cmd run build

Set-Location D:\codex
& .\.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8888 --workers 1
```

| 入口 | 地址 |
|---|---|
| 咨询 | `http://127.0.0.1:8888/` |
| 后台 | `http://127.0.0.1:8888/admin.html` |
| 健康检查 | `http://127.0.0.1:8888/health` |
| 接口文档 | `http://127.0.0.1:8888/docs` |

工程约束：

- 当前按单 worker 运行，不依赖多进程任务协调。
- 首次空库需先录入并审核教学样本，否则按规则转人工。
- 已安装依赖且已构建前端时，日常只运行最后两行。
- `Dockerfile` 为包含前端的多阶段镜像配置；`docker-compose.yml` 配置 `8888` 端口与 `state` 数据卷。
- Docker 配置已提供，但尚无本机容器实际运行证据。

## 10. 测试、验收与质量保障

后端回归测试：

```powershell
Set-Location D:\codex
& .\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

真实模型验收：

```powershell
& .\.venv\Scripts\python.exe scripts\verify_live.py
```

质量保障要点：

- 后端使用 unittest 做回归测试。
- 浏览器场景使用 Playwright + 本机 Edge。
- 真实模型验收使用隔离数据库，报告写入 `data/acceptance_live.json`，会消耗 API 配额。
- 当前已有 21 项后端测试、3 项浏览器场景，以及真实 Qwen 五轮咨询、红线测试、优化与回放记录。
- 模型桩与真实调用边界见整改验收记录。
- 浏览器验收及停止方法见启动指南；五分钟流程见 `DEMO.md`。

## 11. 可观测性与审计

- 执行轨迹记录决策摘要、Prompt 版本、工具参数/结果/耗时、错误与兜底状态。
- SSE 持久化请求 ID 与事件序号，支持心跳、取消与续读。
- 工单统一落库去重，支持接单与处理。
- 训练样本、知识库与 Prompt 均包含审核、发布、回滚或审计相关能力。
- 运行指标可导出，用于技术验证与问题定位。
- 本地事件与指标不能解释为真实用户量、咨询转化率或商业收益；模型自评不是客观正确率。
- 执行轨迹不包含隐藏思维链。

## 12. 已知工程边界与风险

- 当前是单机本地原型，按单 worker 运行；没有登录、生产级访问控制或多进程任务协调。
- 首个完整安全句实测中位数约 `3.1s`，尚未达到 `2s` 目标。
- 商品与订单为模拟数据；真实业务案例需要提供经确认的资料。
- 向量检索为轻量本地哈希向量方案，不是 Chroma 或语义 embedding 模型；相似度不等于回答正确率。
- Docker 配置已提供，尚无本机容器实际运行证据。
- 不实现真实支付、实时坐席系统、自动发布 Prompt 或 fine-tune。
- 模型自评、本地事件与指标仅用于技术验证，不能外推为商业指标。

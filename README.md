# 企业级智能售前 Agent 平台

面向企业级售前咨询场景的 Agent 平台原型。针对原有模式中工具硬编码、多轮对话信息截断、优化依赖人工翻日志等业务瓶颈，本项目构建了一套**工具可插拔、状态可管控、执行可追溯**的 Agent 执行底座（Harness Runtime），并跑通了“失败分析 → 变更提案 → 人工审核 → 回归验证”的 **AI 自进化闭环**。

在工程底座之上，本项目进一步将意图路由、上下文压缩、知识检索、转人工和回归门禁建模为**可评测、可消融、可校准的算法问题**，形成带 baseline、离线实验协议、统计置信区间与失败归因的 Agent 策略优化平台。

> 说明：文中“当前实现”指已落地能力；“算法升级设计”指可扩展的算法化建模与实验协议。本地事件与指标仅用于工程与算法回归验证，不解释为真实商业收益。

---

## 1. 工程目标与非目标

### 1.1 工程目标

- 提供可本地运行、可演示、可自动化回归测试的售前 Agent 底座。
- 以 `LLMProvider` 和 `Tool` 双抽象及注册表构建底层 Runtime，解耦模型接入与业务逻辑。
- 通过 **Harness 运行时**承载 ReAct 决策循环，实现统一执行护栏：单工具 10s 超时、总预算 60s、最多 6 步。
- 实现多轮会话状态不丢失：底层统一管理 8000 Token 输入预算，超 80% 触发四级动态压缩。
- 依托 Trace 采集构建**自进化评测闭环**，将异常转为 Observation 回灌自我修正，支持 Docker 隔离环境与自动化门禁拦截。
- 将关键启发式模块升级为**成本敏感路由、预算约束上下文选择、证据充分性判定、置信度校准与统计门禁**，并提供可复现的离线实验协议。

### 1.2 非目标

- 不将本地事件与指标解释为真实商业收益；执行轨迹不包含隐藏思维链。
- 不实现真实的自动化支付、实时坐席接管及多进程高并发调度。
- 不堆砌无数据支撑的强化学习、DPO 或多智能体名词；算法升级需配套 baseline、消融与置信区间。

## 3. 核心架构与算法设计

### 3.1 Harness 运行时与工具编排

**当前实现**：接入 6 个真实接口与 2 个 Mock，支持无依赖并行与依赖串行（`tool_call_id` 批量回填）。新增工具仅需注册即可无缝接入，不改主循环；异常自动转为 Observation 回灌。

**算法升级设计**：将工具编排视为**约束序列决策问题**。

- 工具选择与参数补全受单工具超时、总预算、最大步数约束；
- 依赖工具按 DAG 并行调度，非依赖工具减少串行等待；
- 重试策略基于历史成功率与剩余预算做 bandit/规则混合选择；
- 报告指标：任务成功率、平均步数、超时率、工具调用准确率、P95 延迟。

### 3.2 成本敏感意图路由与快慢路径调度

**当前实现**：基于前置意图识别，将简单问答分流至 RAG 生成路径，复杂任务进入 ReAct 工具循环，减少简单请求的工具调用开销。

**算法升级设计**：构建**成本敏感路由**。

- 估计简单问答置信度，并进行温度校准/保形预测；
- 联合估计工具收益、Token 成本与延迟成本；
- 在误路由成本约束下最大化期望效用，选择 RAG 或 ReAct；
- 阈值扫描输出路由准确率、误路由成本、工具调用下降、P95 与 Token 成本变化。

### 3.3 状态机强管控知识资产

前置强制“审核通过且版本有效”，修改后重审重算向量，撤回即标失效。整合专家教学、点评纠偏等来源，封装标准化的人机协同（Human-in-the-loop）接入流程。

### 3.4 预算约束下的四级上下文压缩

**当前实现**：用量超 80% 触发四级压缩——工具结果裁剪、历史摘要归档、画像去重合并、关键槽位存档，保障多轮对话状态不丢失。

**算法升级设计**：将压缩建模为**预算约束的信息保留最大化问题**。

- 对槽位、实体、证据、历史轮次做重要性打分；
- 结合 MMR/子模选择降低冗余，保留引用证据与关键业务槽位；
- 对四级压缩做逐级消融，验证触发阈值与压缩顺序；
- 报告指标：长对话 QA 准确率、引用保持率、Token 降幅、压缩耗时。

### 3.5 混合检索、重排与证据充分性判定

**当前实现**：支持 BM25 + 向量混合召回、Query 改写与证据溯源。

**算法升级设计**：

- 增加 CrossEncoder 重排，报告 Recall@k、nDCG；
- 构建证据充分性分类器，低充分性走拒答或转人工；
- 对拒答置信度做校准，输出无依据率、引用准确率、转人工率 Pareto；
- 检索与生成分离评测，定位失败来自召回、重排还是生成。

### 3.6 转人工风险覆盖优化

**当前实现**：低置信度或规则命中触发转人工创建工单。

**算法升级设计**：将转人工视为**风险覆盖问题**。

- 校准模型置信度，结合保形预测控制漏转风险；
- 绘制转人工率—无依据率 Pareto 曲线；
- 报告转人工率、漏转率、风险覆盖率、AUC/ECE。

## 4. 运行时链路

1. API 层接收咨询请求，基于组织校验与独立 `thread_id` 实现**会话隔离**。
2. 前置意图识别进行**快慢路径调度**：简单问答走 RAG，复杂任务进 ReAct 循环。
3. Harness 按注入式 Loop 组织上下文，程序强制调用知识检索接口，获取审核通过的有效样本。
4. 模型按需调用分析、多路召回（BM25+向量）、重排、工单查询等工具。
5. **执行护栏生效**：单工具 10s 超时、总预算 60s，异常转为 Observation 回灌自我修正。
6. SSE 出口仅放行最终回答增量与引用事件，防止中间态数据泄漏。
7. 低置信度或规则命中，触发转人工创建工单。
8. 采集结构化 Trace（`request_id`、决策摘要、耗时等），按 6 类模式归因失败，沉淀 Badcase。

## 5. 自进化评测与质量保障

### 5.1 离线策略迭代闭环

“失败分析 → 变更提案 → 人工审核 → 回归验证”闭环包含：

- **失败归因分类器**：以 6 类失败为标签，输入 Trace 特征，输出归因概率；人工审核作为弱监督。
- **候选 Diff 生成**：携 Tool 抽象与 `pytest` 样例，交由 Claude Code 生成候选 Diff。
- **Docker 隔离验证**：在隔离环境执行单调与固定回归子集，重点检查价格、权限等关键用例。
- **统计门禁**：候选 Diff 的通过率差使用 bootstrap 置信区间/序贯检验判定，置信区间下界低于阈值则拦截或回滚。
- **主动学习采样**：从 Badcase 池选择信息量最大的样本进入回归集，降低固定样本维护成本。
- **人工审核**：业务语义由人工确认后合入，对引入回归的变更执行拦截或回滚。

### 5.2 实验协议

所有算法升级遵循统一离线实验协议：

- **数据切分**：训练/验证/固定回归集/holdout 分离，避免同一 Badcase 反复调参泄漏。
- **Baseline**：规则路由、纯截断压缩、纯向量检索、无重排、无校准转人工。
- **消融**：逐项去掉路由校准、重排、证据充分性、四级压缩、统计门禁。
- **统计**：报告均值与 bootstrap 95% CI；小样本任务报告通过率区间而非单点。
- **失败分析**：按召回失败、重排失败、证据不足、工具错误、上下文丢失、生成越界 6 类归因。
- **边界声明**：本地单机单 worker，指标仅代表本地评测事件。

### 5.3 已报告指标

- **自动化门禁**：累计拦截 3 次异常合入（含 1 次回滚），保障 60 条核心回归集 90.0% 通过率。
- **双标注与泛化**：双标注一致率 93%（κ = 0.854），holdout 泛化差距 2.5pp。
- **效能与修复**：42 条基线失败聚类 6 类，实修 36 条（85.7%），复测通过 83.3%；11 次修复验收 9 项，交付中位 34 分钟。
- **业务稳定性**：120 条任务覆盖 7 类场景，成功率 65.0%—90.0%；无依据率 20.0%—3.3%，转人工率 12.5%。
- **性能与成本**：端到端 P50 8.2s / P95 24.5s；综合成本 0.13—0.66 元/次，较纯人工降本 86%—93%。

## 6. 快速开始

```bash
# 1. 启动服务（含前端多阶段镜像）
docker compose up --build

# 2. 访问咨询平台/后台管理
# http://localhost:8888

# 3. 运行后端回归测试
pytest tests/

# 4. 运行真实模型/浏览器验收（按需）
python scripts/verify_live.py
```

默认使用本地 SQLite 与 `state` 数据卷；本地单机单 worker 运行，向量检索支持扩展至重排模型。

## 7. 项目目录与模块职责

```text
agent/                  售前业务、样本、工具、知识检索、Prompt 与优化

data/                   默认数据库、模拟商品与订单资料
scripts/                样本导入、隔离真实模型/浏览器验收服务
tests/                  pytest 后端回归测试
Dockerfile              包含前端的多阶段镜像配置
docker-compose.yml      8888 端口与 state 数据卷配置
```
